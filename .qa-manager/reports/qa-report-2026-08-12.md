All backend (337) and frontend (63) automated tests pass after the fixes. Several additional findings from code review were investigated and are documented as deferred below, with reasoning.

## Issues found and fixed

### ISSUE-001 — CSP `script-src` blocked all inline hydration scripts (Critical)
**Category:** Functional / Security
**Found via:** live browser testing
**Commit:** `e6df249`

The CSP added in `worker/index.ts` (`script-src 'self' 'wasm-unsafe-eval'`, no `unsafe-inline`, no nonce) blocked every inline `<script>` tag the framework emits to stream RSC/SSR hydration data. Confirmed live: clicking the Source/English toggle threw *"UNHANDLED SCRIPT ERROR — the server could not finish this Suspense boundary"* and never updated. Every button, tab, and toggle on the page was affected identically — this was effectively a broken app on first interaction. It went unnoticed because the same-day PRD audit's browser tooling had become unavailable partway through that session (documented in `docs/reports/PRD-READINESS-AUDIT-2026-08-12.md`, gap A-3).

**Fix:** `frontend/proxy.ts` implementing the documented Next.js CSP-nonce pattern. Each request gets a random nonce forwarded via request headers so the renderer stamps every inline script with it, reflected in the response CSP so the browser allows exactly those scripts. Verified: all inline scripts now carry the matching nonce (checked programmatically and confirmed live — the English toggle now works with zero console errors).

### ISSUE-002 — Hidden upload file input has no accessible name (Medium, accessibility)
**Category:** Accessibility
**Found via:** live browser + JS accessibility scan
**Commit:** `3b4c088`

The file input uses the screen-reader-only `visually-hidden` CSS pattern (not `display:none`), so it stays keyboard-focusable and in the accessibility tree — but had no `aria-label`. A keyboard/screen-reader user tabbing through the page would land on an unlabeled file input.

**Fix:** `aria-label="Upload document"` matching the visible button that triggers it.

### ISSUE-003 — PII redaction dedupe drops overlapping spans instead of merging (Critical, security)
**Category:** Security / Correctness
**Found via:** independent multi-angle code review (3 of 4 review passes converged on this independently)
**Commit:** `fd9be07`

`dedupe_overlaps()` picked one span per overlap group (earliest start, then longest) and **discarded the other entirely**. When the discarded span extended past the kept span's end — e.g. an email nested inside a matched URL, or a longer ID/phone match starting just inside a shorter match — the discarded span's non-covered tail was never tokenized and would reach the generative LLM provider **in cleartext**. This directly contradicts the Security Gateway's fail-closed pseudonymization guarantee (`AGENTS.md` security boundary 7).

Confirmed repro: `"See http://example.com?contact=jane@example.com for details"` — the URL span (starts earlier) was kept and the nested email span was dropped outright.

**Fix:** merge overlapping spans into one covering span instead of picking a winner, so every character any detector flagged is masked regardless of which span "wins" the category label. Also corrected an existing test that had (unknowingly) hard-coded the vulnerable behavior as its expected output.

### ISSUE-004 — Upload idempotency fingerprint never hashed the file's bytes (High, correctness)
**Category:** API / Data integrity
**Found via:** independent multi-angle code review
**Commit:** `49e6873`

The idempotency fingerprint was built from filename/content-type/data-class/processing-profile only. Replaying the same `Idempotency-Key` with a genuinely different file (same filename and content-type — e.g. a corrected version of the same document) fingerprinted identically to the first request. The client would silently get back the **first** document's cached response instead of the new file being processed — contradicting the module's own documented contract ("the same key with a different body is rejected").

**Fix:** stream-hash the file's actual bytes before the idempotency check and fold the digest into the fingerprint (`seek(0)` afterward so the normal upload path still streams from the start).

### ISSUE-005 — Idempotency scope built via colon-concatenation can collide across principals (High, security)
**Category:** Security / Multi-tenancy
**Found via:** independent multi-angle code review
**Commit:** `668a3ff`

`idempotency_scope()` built the DB uniqueness key as `f"{org}:{subject}:{operation}:{key}"`. `organization_id`/`subject` come from operator-configured principals or JWT claims and aren't restricted to a colon-free charset, so two distinct `(org, subject)` pairs could concatenate to the identical scope string. A collision would let one principal's reservation be read as another's, and in the fingerprint-match case, replay a different principal's cached response — including its `resource_id`.

**Fix:** reuse the existing null-byte-delimited `request_fingerprint()` hashing scheme instead of delimited concatenation.

## Live verification performed

- **Functional:** full document-studio walkthrough (page nav, zoom/rotate, table inspection, Source/English toggle, Financial/Page/JSON tabs, Recent-documents panel, re-opening a real prior document, garbage-file failed-extraction state with graceful "Preview unavailable" + Retry) — all correct, no console errors after fixes.
- **Responsive:** 375px (mobile), 768px (tablet), 1280px (desktop) — clean stacked layouts, no overlap or horizontal scroll.
- **Performance (production build):** DOM Content Loaded 536ms, Load 671ms, First Contentful Paint 596ms, 10 requests, 529KB transfer — well within budget. (Dev-server numbers are not representative and were not used for this assessment.)
- **Security spot-check:** no secrets in rendered HTML, no cookies (auth is bearer-token via a server-side proxy that never reaches the browser, already covered by an existing test), CSP/HSTS/X-Frame-Options/etc. present on both frontend and backend.
- **API testing (direct, via curl against the FastAPI backend):**
  - Auth matrix: no token → 401; invalid token → 403; valid token → 200.
  - 404 for a non-existent document id.
  - Path traversal on the download-artifact endpoint → 404 (blocked).
  - Upload: missing file → 422; disallowed extension → 422; client-requested processing-profile escalation (`GENAI_RAW_EXCEPTION`) → **blocked** (fail-closed enforced, per `AGENTS.md` invariant 11).
  - CORS: allowed for the configured frontend origin, correctly absent (blocked) for an arbitrary origin.
  - Malformed JSON body → 422, safe machine-readable error, no stack trace.
